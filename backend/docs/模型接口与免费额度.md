# 模型接口、自带 key 与每日免费额度

生成时间：2026-10-02
适用范围：`backend/`（厂商名单、额度层、三个 AI 端点）与 `frontend/`（API 设置页、起卦页提示条）

---

## 一、这套东西要解决什么

原来只有一条路：**站长付钱**，用户白用。配额是"每 IP 每天 50 次 + 全站软 80 硬 100"。
开源并公开部署之后，这条路不能是唯一的——别人自建一份，若默认由部署者承担全部 AI 成本，就没人敢公开。

于是改成两条路：

| 路径 | 谁付钱 | 次数 | 走哪条闸 |
|---|---|---|---|
| 用户填了自己的模型 key | 用户自己（在模型厂商那边的账户） | **不限次数** | 不计数、不拦截 |
| 没填 key | 站长 | **签到后每天 3 次**，跨天不结转 | 签到 + 设备 + IP + 全站四道 |

站长的原话（2026-10-02）："每 IP 每天 50 次的免费额度去除，因为我定义的是用户自己可以调用他自己的 api，
这样他就可以无限 ai 解卦，然后对于没有 api 的用户就给他每日三次的 ai 解卦。"
另加一条："不能累加，昨天的免费次数，不能和今天的免费次数累加。"

**排盘、卦象、体用、处方五行、应期日期全部由代码算定，两条路都不花钱、也不受额度影响**——
额度只管"AI 白话解读"那一段。

## 二、厂商名单：为什么地址由服务端写死

用户在设置页只能做三件事：**选厂商、填 key、改模型名**。地址（base_url）来自服务端的预设名单。

理由不是"省事"，是安全：后端要拿"用户给的地址"去发请求，若地址可由客户端指定，本站服务器
就成了任意地址的转发器（SSRF：可以被打内网、被当成别人的代理）。**模型名不影响请求去往哪个地址**，
所以允许手填（各家模型更新很快）；地址则一律白名单。

名单与出处（2026-10-02 逐一查证官方文档）：

| 厂商 | 接口地址 | 默认模型 | 文档里还写了什么 |
|---|---|---|---|
| DeepSeek（推荐） | `https://api.deepseek.com` | `deepseek-flash` | OpenAI/Anthropic 双格式兼容；旧名 `deepseek-v4-flash` 仍被接受但按 Flash 计费 |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` | `kimi-k3` | OpenAI Chat Completions 兼容 |
| 智谱 GLM | `https://open.bigmodel.cn/api/paas/v4` | `glm-5.3` | 官方注明"某些场景下与 OpenAI 接口仍存在差异" |
| 通义千问（阿里云百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen3.8-max` | **key 按地域绑定**，用错地域会 401 `invalid_api_key`；文档称原 dashscope 域名仍可用，但推荐业务空间专属域名 |
| 豆包（火山方舟） | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-2-1-pro-260628` | 文档自述"兼容 OpenAI SDK" |

**未查证、也不假装查证的两件事**：

1. 除 DeepSeek 外，其余四家是否容忍本站请求体里的 `thinking` 字段（DeepSeek 专有，用来关掉推理模型的
   思考阶段，避免预算全烧在 reasoning 上）。官方文档都没写，所以代码里的做法是**只对 DeepSeek 发这个字段**
   ——不依赖"未知字段会被忽略"这种假设。
2. 四家的**流式**响应字段是否与 OpenAI 逐字一致——**这个问题已不存在**：2026-10-06 站长拍板把解卦改成
   **上游非流式**（整段生成后一次发出，外层仍是 SSE 封装，前端不变）。理由：非流式的最终 JSON 是
   OpenAI 兼容格式里各家最一致的部分，解析类报错更少。代价（写在这里，不是没看见）：长解卦要等上游
   生成完才显示（前端显示"解卦中…"）；120 秒超时内必须整段生成，超时则这一次什么都没有。

**真实 key 实测记录（2026-10-06，每家一次最小请求，经「测试连接」接口，五家全部通过）**：

| 厂商 | 实测模型 | 结果 |
|---|---|---|
| DeepSeek | deepseek-flash | 连接成功（站长付费 key） |
| 豆包（火山方舟） | doubao-seed-evolving | 连接成功 |
| 通义千问（百炼） | qwen3.8-flash | 连接成功 |
| 智谱 GLM | GLM-5.3-Flash | 连接成功 |
| Kimi | kimi-k2.6 | 连接成功 |
| Kimi | kimi-k3 | HTTP 404「Not found the model kimi-k3 or Permission denied」——k3 需账号开通权限，未开通即 404 |

由此得到一条对产品成立的事实：**模型名与账号开通状态有关**（同一家厂商，不同账号能用的模型不同），
所以模型名必须允许手填；默认模型取实测通过的这五个。

## 三、key 的边界（写进代码，也写进页面）

- key 只存在**用户自己的浏览器**（`localStorage`，键名 `bagua_llm_setting`）。
- 解卦时它随那一次请求交给后端；后端**只在本次请求的内存里**用它调上游——
  **不写数据库、不写日志、不写提示词调试文件**。有一条测试专门盯这件事
  （`test_byok_key_never_reaches_the_log`：断言决策日志里搜不到 key）。
- 「测试连接」只回成功与否与一句原因，**不回模型原文**——否则本站就成了免费的模型试验场。
- 没配 key 时前端**不带** `llm` 字段（而不是带空的）：后端对"带了厂商却没 key"是按配置错误处理并如实报错，
  对"什么都没带"才是走免费额度。两者语义不同，不能混。

## 四、额度：四道闸，各自的理由

顺序：**全站 → 签到 → 设备 → IP**（全站已满时不再计任何数，免得计数虚涨）。

| 闸 | 值（可用环境变量改） | 防什么 |
|---|---|---|
| 全站硬阈值 | `QUOTA_SITE_HARD=100`/天 | 成本天花板：一天最多花多少钱 |
| 全站软阈值 | `QUOTA_SITE_SOFT=80`/天 | 只发一封告警邮件，不拦人；比硬阈值低，邮件才来得及起作用 |
| 签到 | 一天一行（`signin_daily`） | 让用户知道额度有限；重复签到幂等，不加次数 |
| 每设备 | `QUOTA_FREE_AI_DAILY=3`/天 | 这是"给没有 key 的人每天 3 次"的落点 |
| 每 IP | `QUOTA_FREE_IP_DAILY=20`/天 | 防"清掉本地令牌再签到"反复刷；值大于真人用量，避免大 NAT 误伤 |

**跨天不结转怎么实现的**：用量按 **(日期, 设备)** 记行，不存"余额"。
新的一天没有那一行，于是从 0 起算——昨天的剩余次数在存储里根本不存在，无法被结转。
有一条测试专门盯它（`test_no_carryover_from_yesterday`：往库里写"昨天用过 1 次"的行，
断言今天仍从 3 次起算）。

重置时点一律按**北京时间 0 点**（显式 +08:00，与服务器时区无关）——页面承诺"明天 0 点重置"必须真的成立。

## 五、接口一览

| 接口 | 作用 | 备注 |
|---|---|---|
| `GET /api/llm/providers` | 厂商名单（含每日免费次数） | 只回 id/名称/说明/默认模型/候选模型/申请入口，**不含地址与密钥字段** |
| `POST /api/llm/test` | 用用户的 key 发一句最小请求 | 限流 10 次/分钟；只回成功与否与原因 |
| `GET /api/quota/status` | 本设备今日免费额度（只读） | 不产生用量 |
| `POST /api/quota/signin` | 今日签到（幂等） | 限流 10 次/分钟 |

请求体（`/api/meihua/divine`、`/api/liuyao/divine`、`/api/meihua/chat`）多一个可选字段：

```json
{ "llm": { "provider": "deepseek", "api_key": "sk-...", "model": "deepseek-flash" } }
```

它的存在与否决定走哪条路：

- 带 key 且厂商在名单里 → 用用户的 key 与地址，**不计数**；
- 带了厂商但没 key、或厂商不在名单里 → SSE 一帧 `degraded`（`scope=llm`），
  **如实报错，不静默退回免费路径**（否则用户以为在用自己的 key，实际在花站长的钱）；
- 什么都没带 → 免费路径：未签到 → `scope=signin`；当日 3 次用完 → `scope=device`；
  IP 兜住 → `scope=ip`；全站到顶 → `scope=site`。

三种降级都**照常把卦给全**（排盘/卦象/体用/处方五行/应期一个字不受影响），只少一段白话。

## 六、自建部署者要注意的两件事

1. **本站 key 可以不配**：代码里"有没有 LLM"的判断是 `llm_ov or LLM_CONFIG["api_key"]`，
   自带 key 也算有——这样零成本的纯 BYOK 部署是成立的（这条曾经写漏过，有测试盯着：
   `test_byok_does_not_touch_quota_and_uses_user_model` 就是靠"把本站 key 清空"跑通的）。
2. **全站硬阈值要按自己的预算调**：3 次/设备 × 每天 34 台设备就会顶到 100 次。
   免费用户多的站要上调 `QUOTA_SITE_HARD`，否则用户会看到"今日额度已满"。

## 七、已知局限（写在这里，而不是假装没有）

- 单进程 + SQLite：多进程/多机部署时各算各的（本站固定单 worker）。要横向扩容得换成共享存储。
- 清掉浏览器数据就能重新签到——IP 兜底与全站硬阈值是为此留的，不指望签到本身能防刷。
- 只统计"发起调用"这一下，不区分上游是否真的成功（宁可多算，不可少算）。
- 厂商名单的模型名会过时（各家迭代很快）：名单里的候选只是"写这份文档时官方文档上的名字"，
  过期了手填即可，不影响请求去往哪个地址。
