# 提示词检校流程

> 这份流程来自 2026-09 对梅花解卦提示词的一次完整检校（7827 → 5194 字，374 → 389 测试）。
> 目的是让六爻那一遍**不必从零摸索**。所有"坑"都是真实踩过的，不是设想。

---

## 0. 提示词为什么需要"检校"而不是"改写"

提示词是代码的一部分，但它的错误**不会崩**——只会让 AI 悄悄说错话，用户看不出来。实际遇到的四类：

| 类 | 例子（真实） | 后果 |
|---|---|---|
| **串库** | 六爻提示词里拿《梅花易数·衰旺论》当"标篇名"的例子 | AI 照抄，六爻断语里出现梅花篇名 |
| **自称与实情不符** | 自称"以下十条规矩"，正文只有九条，且「四、」重号 | AI 按十条的框架讲话，规矩编号自己都乱 |
| **镜像漂移** | 代码 3679 字，文档 §5 只镜像了 1037 字 | 下一个人照过期文档继续改，越改越远 |
| **"引文"其实不是原文** | 取象表标点被规范过、漏整句、混进书里没有的句子、讹字 | 对着用户"引原文"，引的是二手改写 |

前三类**机器可查**（见 §2）；第四类只能人工对着 `books/` 核，也是**唯一不能省的步骤**。

---

## 1. 三条铁律（先立规矩再动手）

1. **只改 `backend/` 与 `frontend/`**。`books/` 是只读参考，绝不改、绝不"顺手订正"。
2. **绝不代拟**。书里没有的规则，不许自己写一条塞进提示词。找不到依据就写「此条典籍未载」。
3. **数字来源唯一**。代码能算的，由**代码算好注入**；AI 只读不算。AI 自己推出来的数字就是编。

---

## 2. 流程（八步）

### 第一步 · 建基线

```
cd backend
python tools/prompt_audit.py
```

记下字数/行数、镜像状态、确定问题数。**这份输出就是"改前"的底片**，改完要能对比。

### 第二步 · 读机械体检结果

- `✗` 自洽性破 / 串库 / 镜像漂移 → 必修
- `?` 重号 / 重复句 → **机械只给候选，判断权归人**。六爻第 16 行的「一、二、三」是**句中枚举**（列举取用神的三种常法），不是标题，不要误改。

### 第三步 · 逐字纪律核查（唯一不能省的步骤）

凡是提示词里写了"原文""引文""《…》谓"的句子，都要对着 `books/` 核。方法：

1. **不要手抄。手抄必错。** 用起始锚点 + 类末收束句从语料里**机器抽取**：
   ```python
   flat = re.sub(r"\s+", "", read_corpus())   # ★ 必须先摊平：PDF 折行会往句中插空格
   a = flat.find("云开见日")                   # 起始锚点
   b = flat.find("此乃仰观天文", a)            # 收束语，且要求 b-a < 400
   text = flat[a:b]                          # 收束语本身单列成 label，不进正文
   ```
2. **两本都有就两本对校**（`find` 取靠前的、`rfind` 取靠后的），差异逐条留档到 `variant`，**不替任何一本改字**。
3. **电子文本本身有残**，判定规则：
   - **脱字致句残**（如底本「遇瞽者」脱「瞽」）→ 该条入用改取另一本，底本原字仍进 `variant`；
   - **单字之讹**（卞贾/巨贾、亦于/亦与）→ 用底本 + 记异文；
   - 段落里带 `【`（白话释意）或 `<`（HTML 表格）→ **不可直接引用**，改用另一本。
4. 抽完必须回验：`assert text in flat`，且逐条打印出来人眼过一遍。

### 第四步 · 找重复与冗余

`prompt_audit.py` 的"重复句"只抓 ≥14 字**完全相同**的句子；**换着说法的重复它抓不到**，要人读。

经验：冗余集中在**同一条原则被写了三遍**——开头总纲、中间规矩块、末尾「重要」块各一遍。梅花那一遍合并了 8 组（不得重算 ×3、数理与事理并重 ×3、「重要」两条与素材边界逐字同义…）。判断标准只有一条：**是不是同一件事换了个说法**；是就留一处，不是就别动。

### 第五步 · 找数据缺口（代码算了却没给 AI）

问一句：**这个判断，代码是不是已经算出来了？**

梅花那次查出的缺口：`_get_qi_info()` 算了 `wuxing_status`（时令五行旺衰），但 `build_user_prompt` 从没注入过——AI 只能自己推。

- **查法**：`build_*_user_prompt` 实际注入了哪些字段，与引擎算出的字段逐项对比。
- **补法**：**引擎把中间量存进 `method_params`，提示词只负责念出来**。例：`engine._derive()` 把「哪个数、除几、余几、得几」存下，提示词侧只格式化，不重算。余数为 0 要显式写「（余 0 视为 6）」，否则 AI 读成"没有余数"。

### 第六步 · 决定要不要拆提示词

一条判据：**回答同一个问题的不同"入口"，该不该合用一份提示词？**

- 梅花：整卦解读 vs 单条外应解读 → **拆**（`INTERPRETATION_SYSTEM_PROMPT` / `OMEN_SYSTEM_PROMPT`），按请求里有没有 `waijing` 二选一，**替换而不是叠加**。叠加会让 AI 顺手把整卦重解一遍，重复且冲淡重点。
- 六爻可能的同类切口：**整卦断** vs **单问追问** vs **应期专断**。先看现有端点是不是共用一份，再决定。

拆出来的那份要写死「只做一件事」和「不许做什么」，并把判据来源钉成"由代码判定，直接用、不得改写"。

### 第七步 · 落地与测试

- **一次改成一份权威版本**，不要多次部分打补丁。本项目曾因部分替换（脚本报 8/12、10/12）把文件改花，最后只能整份重写。
- 测试**钉语义，不钉措辞**：
  - 「自称 N 条」写成**自洽性断言**（自称数 == 最大连续编号段的条数），不要写死 `"十条规矩"`——那条断言当时锁住的正是 bug 本身。
  - 字讹守卫要**跟着文本走**：文本从提示词搬进 JSON，断言也搬过去，不是删掉。
  - 措辞因瘦身而合法改变时，把断言改成钉"这几项内容都在"，而不是钉旧句子。
- 每改一次，跑三件：`pytest` → `prompt_audit` → `sync_prompt_mirror`。

### 第八步 · 镜像同步与服务重启

```
python tools/sync_prompt_mirror.py            # 看差异（默认不写）
python tools/sync_prompt_mirror.py --write    # 写回
```

- **AI 读的是代码，不是文档。只改文档等于没改。** 反过来，代码改了文档没跟上，会误导下一个人。
- **常量和 JSON 是导入时读的**：`waijing_xiang.json` 这类改完**必须重启后端**才生效。重启后确认监听进程的**启动时间晚于文件修改时间**，否则你测的还是旧代码。

## 3. 六爻这一遍的起手（已探到的四条款索）

- **对象**：`LIUYAO_SYSTEM_PROMPT`（`main.py:1622`，3679 字 / 75 行），底本《增删卜易》（野鹤老人）＋《卜筮正宗》（王洪绪）。对应文档 §5。
- **串库（必修）**：第 50 行拿「《梅花易数·衰旺论》」当"标出篇名"的例子。六爻的旺衰本应是**四时旺相**，而 `book_quotes.py` 里已经有「增删卜易·四时旺相」「卜筮正宗·四时旺相」两条现成书证可换。
- **镜像漂移（必修）**：文档 §5 只有 1037 字 vs 代码 3679 字，**从代码第 338 字起分叉**——doc 从「用神之外有三神…」直接跳到「二、世应关系」，整段漏了**元神/忌神/仇神**。跑 `sync_prompt_mirror.py --write --only LIUYAO_SYSTEM_PROMPT` 可修；建议先把代码那份读完再同步，免得把问题也一起固化。
- **逐字核查的重点**：`book_quotes.py` 现有 52 条引文，**六爻相关只有 4 条**（增删卜易·用神章 / 四时旺相 / 六冲章、卜筮正宗·四时旺相）。引用密度远低于梅花，所以六爻提示词里那些"《增删卜易》谓…"很可能**从未对过原文**——这是这一遍最可能挖出东西的地方。

### 六爻专属的"数据缺口"候选（第五步用）

梅花缺的是"旺衰没注入"。六爻同类问题大概率在这些地方，逐一确认代码算了没有、注入了没有：

- **旬空 / 月破 / 日破**——空亡表、月破日破的判定，是否已由代码算定并注入？
- **飞伏**——伏神是否出、飞来生伏 / 伏克飞，`test_prompt_b_batch.py` 里已有「飞来生伏得长生」「飞神空破休囚墓绝」的断言，说明提示词在讲规则；**规则是 AI 自己套，还是代码算好了？**
- **进神 / 退神 / 反吟 / 伏吟**——同上。
- **应期**——「月破者实破之日」「冲开之月日应」在提示词里，但梅花那边应期是**代码算好日期、AI 只许逐字引用**。六爻的应期日期是不是也由代码给出？如果没给，AI 就会自己推干支（编造）。

## 4. 已查实的坑（真实记录，可直接对照避坑）

| # | 坑 | 怎么发现的 | 教训 |
|---|---|---|---|
| 1 | 提示词自称"十条规矩"，正文九条，「四、」还重号 | 通读时数了一遍 | 自称数要写成自洽性断言 |
| 2 | 测试写死 `"十条规矩"`，锁住的正是这个 bug | 改完提示词测试反而红了 | 断言别钉会变的东西 |
| 3 | 提示词的"引文"不是原文（标点被规范、漏句、混入非原文句、讹字「封」应为「卦」） | 拿 `books/` 逐字核对，7/9 条不过 | **要引原文就必须机器抽取** |
| 4 | 以为取象表"挪个地方就行"，其实它在代码里**只有提示词一个落点** | grep 全库只有 2 处痕迹 | 删之前先确认别处还有没有 |
| 5 | 文档同步脚本没断言锚点存在，报"已同步"其实没写 | 事后审计发现 doc 与 code 同长但引号不同 | 同步脚本必须能**验证**，不能只报告 |
| 6 | 部分替换把文件改花（脚本报 8/12、10/12） | 两次 patch 结果对不上 | 一次一份权威版本 |
| 7 | 代码算了旺衰，但提示词从没注入 | 逐项比对注入字段 | 每轮都问"代码算了没给 AI 吗" |
| 8 | ASCII 直引号嵌进 `"""` 字符串，反复自伤 | 语法错误 / 字符串被提前截断 | 统一用「」 |
| 9 | PowerShell 控制台 GBK，打印 `✗` 直接崩 | `UnicodeEncodeError` | 脚本加 `sys.stdout.reconfigure(encoding="utf-8")` |
| 10 | 改完没重启，测的还是旧代码 | 进程启动时间 < 文件修改时间 | 重启后核对启动时间 |
| 11 | 只在文档里改提示词 | —— | AI 读代码；文档只给人看 |
| 12 | 手抄原文必错 | 9 条里错 7 条 | 手抄不可作为交付方式 |

## 5. 命令速查

```powershell
cd D:\Web\bagua\backend

python tools/prompt_audit.py                    # 机械体检（只读）
python tools/sync_prompt_mirror.py              # 看镜像差异（只读）
python tools/sync_prompt_mirror.py --write      # 写回镜像
python -m pytest -q                             # 全量测试

# 只处理某一个提示词
python tools/sync_prompt_mirror.py --write --only LIUYAO_SYSTEM_PROMPT
```

**改提示词的顺序**：读基线 → 机械体检 → 逐字核查 → 去重 → 补数据 → （必要时）拆 → 一次改写 → 测试 → 镜像同步 → 重启。
