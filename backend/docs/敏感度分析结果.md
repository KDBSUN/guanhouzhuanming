# 敏感度分析结果：哪些自定数字一动就变，哪些怎么动都不变

生成时间：2026-09-23
方法：把站里自己编的数字各自上下浮动 20% / 30%，用**线上真实案例**重算，看有多少结论改变。
全程只读线上库（不写任何表、不改任何代码文件）。
每一组都先做"数字不动时能否复现存下来的结果"的校验；**复现不过关的组不出结论**。

---

## 一、结论速览

| 编号 | 测的数字 | 样本 | 浮动 ±20%／±30% 的结果 | 判定 |
|---|---|---|---|---|
| S1 | 八字身强身弱：三项权重 50/30/20、分档线 0.70/0.55/0.45/0.30 | 9 个档案（去重后只有 3 份出生数据、实际是 2 个人） | **一项都没变**（0/9）。要翻档，权重得放大到约 3 倍 | 不敏感（但样本太单一，见下） |
| S2 | 岁运门槛 0.5 | 202 条真实裁决 | 门槛 0.5→0.32 之间：**全都不变**；一降到 **0.30 及以下：103/202（51%）的裁决改变** | 临界型：不动则已，一动变一半 |
| S3 | 流动五行分档线 1.0/3.0/6.0（只影响显示档位与"补多少"的措辞） | 119 个"某五行"条目 | 下调 20%：**67/119（56%）从"弱"变"中和偏旺"**；上调 20%：0 变 | 单向敏感（"弱／中和偏旺"那条线） |
| S4 | 藏干权重 1.0/0.6/0.4（影响乘侮判定） | 238 处 | **未能复现存下来的结果（只对上 28%），故不出结论** | 未完成 |
| S5 | 梅花应期加权 0.80/0.15/0.025/0.025 与门槛 0.45 | 29 个真实卦（可复现 14 个） | **权重降 20%：14/14 个卦的应期日期表全变**；门槛升 20%：**14/14 全变**；门槛降 20%：0 变 | **最敏感的一处** |

一句话：**你现在最该盯的不是那 98 个数字，而是其中 2–3 处**——梅花应期的加权与门槛、流动五行"弱↔中和偏旺"那条线、岁运门槛与"0.3"的关系。其余大部分数字在现有样本上怎么动都不改变结论。

## 二、逐组结果与做法

### S1 八字身强身弱（影响面理论最大，实测最不敏感）

- **样本真相**：库里 9 个命局档案，去重后只有 3 份出生数据，实际是**两个人**（一份 2026-08-05 12 时；八份 2007-03-17 6 时，且其中 4 份是同一份数据的不同存档版本）。9 份档案**全部判为"极弱"**、喜用全是"土、金"、忌神全是"火"。
- **校验**：不动任何数字时，重算出的强弱档与喜忌 **9/9 与存下来的一致**（说明重算管线与线上一致，结果可信）。
- **扰动结果**：三项权重同时 ±20%／±30%、分档线同时 ±30%——**强弱档与喜忌一个都没变**。
- **为什么不变**：那个八字的旺度分是 **0.15**，而"身弱"的下限是 0.30，**差了整整一倍**。做倍数扫描才看出临界点：

  | 三项权重放大 | 旺度分 | 档位 |
  |---|---|---|
  | ×1.0 | 0.15 | 极弱 |
  | ×2.0 | 0.28 | 极弱 |
  | **×3.0** | **0.38** | **身弱** |
  | ×4.0 | 0.45 | 中和偏弱 |
  | ×10.0 | 0.66 | 身旺 |

- **这个结果该怎么读**（很要紧）：不能说"这套数字不重要"，只能说"**在现有这两个人身上，±30% 不足以改变结论**"。原因是样本里所有人的分数都挤在最低档，中高档没人测过。要真正检验这套打分，需要**旺度分在 0.30–0.70 之间的命局**——这些档案目前一个都没有。
- **顺带发现**：旧档案里没有存四柱的干支（4 份档案的干支字段是空的），所以那几份档案只能靠存下来的结论比对，不能参与更细的重算。

### S2 岁运门槛 0.5

- **样本**：202 条带岁运的裁决。**这 202 条的"流年权重"全部是 0.3**——因为都是 2026 年（丙午火）起的卦，火相对各月起卦的月令多处在"囚"位，取值就是 0.3。
- **校验**：门槛不动时复现存下来的档位与门禁 **202/202 一致**。
- **扫描结果**：

  | 门槛 | 裁决改变 |
  |---|---|
  | 0.50（现值） | 0/202 |
  | 0.40 | 0/202 |
  | 0.35 | 0/202 |
  | 0.32 | 0/202 |
  | **0.30** | **103/202（51%）** |
  | 0.25 | 103/202 |

- **怎么读**：门槛只要还在 0.3 以上，**岁运层对这批案例完全不发生作用**（全是"失令近乎不计、仅作背景"）。门槛一旦降到 0.30（也就是"囚"这一档的取值本身），这批案例里一半的岁运立刻转为"参与引动"，可以升降档。所以真正的开关是"**门槛与 0.3 的大小关系**"，不是门槛的具体数值。
- **附带事实**：这也意味着 2026 年起的卦，岁运层在页面上只是背景说明——不是 bug，是当前取值关系决定的。

### S3 流动五行分档线（1.0／3.0／6.0）

- **样本**：120 条裁决里的 119 个"某五行"条目（每条裁决有 1 个要补的五行）。
- **校验**：按存下来的判据值与现分档线复现，**119/119 一致**。
- **扰动**：分档线整体下调 20%（→0.8/2.4/4.8）时，**67/119（56%）从"弱"变为"中和偏旺"**；整体上调 20%（→1.2/3.6/7.2）时，**一个都不变**。
- **怎么读**：敏感的是"弱／中和偏旺"那条线（3.0）。这批案例的判据值大量落在 2.4–3.0 之间，所以线上调 0 个、往下一格就翻一半。
- **影响范围**：这一处**只改显示档位与"宜补而量少"这类措辞，不进裁决**（不改顺/平/逆、不改红黄绿）。所以它影响的是"用户看到的解释"，不是"结论"。

### S4 藏干权重（未完成）

- 目的：测它对乘侮判定（"谁压谁"的标记与"量级修正"）的影响。
- 尝试了两种参数顺序（把"补的那个五行"当攻方／当守方），重算结果与存下来的乘侮判定**各只对上 67/238（28%）**。
- 原因判断：日志里存下来的判据值（攻守双方的分数）与档案现状**对不上**——同一份档案在不同时间被重新保存过，日志记的是**当时**的命局快照，而我现在只能拿到**现在**的档案。存量数据不足以还原当时的输入。
- 因此**这一组不出结论**。要测它，需要日志里把当时的攻守分数一并存下来（现在只存了双方的差值比值）。

### S5 梅花应期的加权与门槛（最敏感）

- **样本**：29 个存了应期结果的卦；其中 **14 个能复现**（另 15 个是应期算法改版之前算的，用现在的算法重算自然对不上，故不参与）。
- **校验**：14 个用起卦日重算，按卦应期日期与存下来的完全一致。
- **扰动结果**：

  | 改动 | 日期表改变的卦 | 日期增减合计 |
  |---|---|---|
  | 加权整体 −30% | 14/14（100%） | 50 个 |
  | 加权整体 −20% | 14/14（100%） | 50 个 |
  | 加权整体 +20% | 0/14 | 0 |
  | 门槛 −30%（0.315） | 5/14（36%） | 13 个 |
  | 门槛 −20%（0.36） | 0/14 | 0 |
  | 门槛 **+20%（0.54）** | **14/14（100%）** | 50 个 |

- **怎么读**：应期表对这两个数字极其敏感——加权降两成就把所有卦的日期表换掉，门槛升两成同样全换。原因是这批案例的旺衰分大量集中在门槛（0.45）附近。**这是全站最该盯的一处自定数字**。
- **注意**：加权降 20% 与门槛升 20% 造成的变化量相同（各 50 个日期），说明两者在这批案例上是等效杠杆。

## 三、这次分析暴露的两个更根本的问题

1. **样本只有一个人**：218 条裁决里 **217 条属于同一个用户**，9 个命局档案去重后只有 2 个人的出生数据。所以上面所有百分比描述的是"**这套代码在你自己的案例上的行为**"，不是"用户群体的分布"。要让敏感度分析有意义，需要不同命局、不同年份、不同卦的案例。
2. **存量日志缺两样东西**：① 当时用的命局快照（现在只能读到最新档案，S4 因此做不了）；② 应期与择日的判据明细（所以 S2、S5 只能做"裁决/日期表层面"的比对，做不了更细的分解）。

## 四、由此看"要不要做公测与反馈"

### 先说结论

- **想靠反馈把这 98 个数字"矫正到准确"：做不到。** 原因是结构性的：术数案例没有对照组，反馈只能告诉你"这条断言没发生/恰好相反"，不能告诉你"这个比例该是多少"。这一点站里自己的代码里已经写明（"术数案例没有对照组，拟合即自欺"）。
- **想让反馈帮忙发现"明显错的规则"：有价值**，但需要的信息不是五档按钮，而是"**实际发生了什么、哪天发生的**"。
- **公测本身不必等反馈**：公测要验证的是产品价值（有人愿意用、愿意付费），这件事不依赖反馈系统是否完善。

### 但敏感度分析改了一件事：需要校准的对象比你以为的少得多

98 个数字里，现有案例上**真正一改就变结论的只有 2–3 处**（梅花应期的加权与门槛、流动五行"弱／中和偏旺"那条线、岁运门槛与 0.3 的关系）。其余大部分（八字三项权重、分档线、藏干权重等）在现有样本上怎么动都不改变结论。

**这意味着两件事**：

1. 你不必为了"校准 98 个数字"去攒大量反馈——**大部分数字不值得校准**，只需在文档里标注"工程默认、未校准、且经敏感度检验对结论不敏感"。
2. 那 2–3 处高敏感数字，恰恰是**最没有反馈通道**的：应期的加权写在代码里（不受版本号管理）、应期也没有任何一条可反馈的断言（反馈面板里的"择日"指的是宜忌日期表，不是应期之日）。所以要校准它们，先得给它们接上通道。

### 你说"现在这样的反馈没几个人会反馈，因为太多太密集"——数据支持你

- 现在的设计：一次校验最多列 **12 条断言**，每条要按 **5 个档位**之一标记（反馈页与结果页都是这样渲染的）。最坏情况**一次要按 60 下**。
- 实际结果：**218 条校验收回 1 条反馈（0.4%）**，而且是"应验"。
- 所以问题不在档位不够细，而在**要求太多**。要提回应答率，方向是**减少提问**，不是加按钮：
  - 只问一句："你问的那件事后来怎么样了？"（应验／未验／还没结果）＋可选填"哪天发生的"。
  - 逐条断言标记改成"想细究的人再点开"的可选项，不做默认流程。
- 这一条改动**不需要动任何判定逻辑**，只动反馈界面的默认流程。

### 建议的优先级（都不涉及改判定）

1. **冻结低敏感数字**：把 S1／S3（上调方向）这批"怎么动都不变"的数字标注为"已冻结"，停止考虑校准它们。
2. **反馈只留最小一问**：一个问题＋可选日期；逐条标记降为可选。
3. **给高敏感数字接上反馈通道**：应期加一条可反馈的断言（"这卦所问之事，实际发生在哪天"），并把应期的加权挪进受版本管理的配置（这样它才有版本号可锚定）。
4. **影子对照**（不需要等用户反馈）：后台用两套参数各算一遍、只展示一套，把另一套的结果也存进日志，事后比差异。这等于把这次做的敏感度分析搬到线上持续做。
5. **攒案例的多样性**：公测时有意收集不同命局（尤其旺度分在 0.30–0.70 之间的），否则"身强身弱"那套永远测不出问题。

## 五、这次没能做到的部分（如实列出）

- **未完成**：藏干权重对乘侮的影响（S4）——存量数据不足以还原输入。
- **未覆盖**：六爻每一爻的旺衰计分（月令五态序分 2／1／0／−1／−2 ＋ 综合二分线 1）、六爻应期窗口 30 天、摇卦的换算常数、档位篇幅、反馈校准护栏。原因是这些数字**没有存进决策日志**（日志记的是裁决与五行层，不记六爻卦的中间量），无法用现有案例做敏感度分析。要覆盖它们，需要在日志里多存几种中间量。
  - 其中摇卦的换算常数我已用另一种方式检验过：在三种真实输入情形下（连续随机参数共 20 万次）四种爻型分布为老阳 12.4–12.6%、少阳/少阴 37.2–37.7%、老阴 12.5–12.6%，与公平铜钱一致，**不存在抽样倾斜**。
- **样本限制**：全部结论基于 218 条裁决（其中 217 条来自一个人）、9 个档案（2 个人）、29 个卦（14 个可复现）。百分比只反映代码行为，不代表人群分布。
- **方法限制**：本分析只测"单参数孤立变化"；没有测两个参数同时变化的交互效应，也没有测"同一参数在不同命局上的不同敏感度"。另外，浮动的幅度口径（±20%/±30%）沿用站里既有的护栏写法，不是从统计功效推出来的。
