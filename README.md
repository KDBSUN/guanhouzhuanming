# 观候·转明

**以传统术数典籍为规则底本的占卜工具**——代码守规则，AI 说人话。

五种占法：梅花易数 · 纳甲六爻 · 四柱八字 · 奇门遁甲 · 大六壬。

---

## 我们与「AI 算命」的分别

### 一、确定性归代码，语言归 AI

吉凶不由模型定。排盘、体用、定用神、处方五行、命卦校验、岁运升降、择日、应期，**全部是可复现的确定性计算**：同一个输入永远同一个结果，且能逐条给出判定依据。AI 只做一件事——把结论说成人话。

> 反过来看：若让模型判吉凶，同一个卦问两次会得到两个答案——术数上这已是死罪。

落地时踩过的坑也写在文档里：行动建议里的「方位／颜色／数字／随身物件」一度**没进过提示词**，判决是对的、落地物却是模型自己编的（同一卦两次可以给出不同方位）。现在类物清单由引擎算好一并交给 AI，实测逐条对得上且它自己标注「据：处方物件清单」。

### 二、逐字回源：页面上每句原文都追得回底本

- **916 条**《梅花易数·八卦万物属类》条目逐字核对（916/916 命中），**214 个**维度行号锚点逐一吻合——手工核对后固化成自动测试
- **60 个出处索引键**（`book_quotes.py`），每键所引每段文字都必须是底本原文的逐字子串
- **162 条**术语原文语录，逐字命中 162 / 未命中 0
- 这条防线抓出过我们自己的错：写「日应」引文时把底本的「寅卯未」当刊误改成「寅卯木」却仍标「原文照录」，测试当场判不过，已改回底本原字

**底本有刊误也照录**，另注义理（例：《观物玄妙歌诀》三副本同讹处，登记待校，不用于操作映射）。

### 三、AI 输出有回检

约束写在提示词里是软的，所以把**判得了**的部分变成硬的：

- **判定级**：正文日期必须落在代码算出的应期表内（实测模型确实在表外补过 3 个日期，其中一个干支还推错了）；书名必须落在提示词已写出的字句内
- **提示级**：措辞偏离只进日志、不上屏（误报率高），带原文片段供人一眼判定
- **判不了的写清楚**：语义级改写（把「顺」说成「尚可」）机器不判——用一个不确定的东西校验另一个不确定的东西没有意义，这类长期留给人看

回检基准必须是「**模型实收的全量**」（system ＋ 每个 user 素材块）。初版只拿 system 当基准，于是模型**照我们自己表头的嘱咐**引了《滴天髓》，被判「编造出处」直接推上屏——现已统一走 `_review_base()` 拼装，并加源码级测试盯住调用点。

### 四、输出没写完就说没写完

AI 输出撞 `max_tokens` 时曾**完全静默**：流安静结束、前端当正常收尾、用户看到一句断在半截的话，系统自己也不知道。根因是一行代码——`_stream_llm` 只取 `delta.content`，把 `finish_reason` 整个丢掉了。

已修：收下 `finish_reason`，`length` 时发 `truncated` 事件并打 WARNING，四个流式端点全部接上（源码级测试盯住每个调用点），前端渲染「**解读未写完**」——并说清三件事：哪里没了、什么没受影响（排盘/用神/处方/应期全是代码算的）、接下来怎么办。

### 五、额度只花在真的要调 AI 那一步

- 摇完六爻或填完梅花参数点「排盘」，出来的**只有盘**——卦象、体用、处方五行、应期
- 要看 AI 白话解读，**再点一下「AI 解卦」**，那一步才扣 1 次
- 对不花钱的东西收费，用户就不敢看盘了，而那个盘恰恰是最该被看到的部分

**额度模型**（`quota.py`，2026-10-02 改版）：

| 闸 | 值 | 行为 |
|---|---|---|
| 每设备每日 | 3 次（签到后） | 免费路径，跨天不结转 |
| 每 IP 每日 | 20 次 | 兜底，防「清令牌再签到」 |
| 全站软阈 | 80 次 | 只发一封告警邮件，**不拦任何人** |
| 全站硬阈 | 100 次 | **只关 AI 解读，不关站**——排盘卦象照常 |

**自带 API key 的用户不走这套**：既不计数也不拦截（花的是他自己的钱），可以无限解卦。

### 六、结论可归因，反馈到断言级

- **决策台账**：每次校验留完整推理链——用哪条规则、按哪版阈值算的，事后能回答「当时为什么判红」
- **断言级反馈**：把一次校验拆成若干条**能判定**的断言，各带验证窗口，到期逐条标记（应验／未验／反向／无法判定／未观察）
- **回执码**：给单条断言签发回执，**不带账号、不带令牌也能作答**，可生成日历提醒（`.ics`）
- **校准有护栏**：只有擦阈样本（判据值离阈值 ≤0.3）进边界台账；样本够护栏（≥5 例、同向 ≥4 例）才生成「待批」提案；**人工批准**后才改阈值并升版本，绝不自动改数
- 数值全部标注「**工程默认值，未经案例校准，仅参与比较／求和**」——术数案例无法做对照实验，**拟合即自欺**

### 七、书上分了几层，建议就分几层

同一条建议，书上给到哪一层精度就给到哪一层；书上没分的不替它分。补金要区分庚金之物（斧钺剑戟钟鼎）与辛金之物（首饰镜鉴），因为《滴天髓》两章标题就是这么写的；而方位／颜色／数字／五味在书上只到五行这一层，就**仍旧是五行级**，不硬拆两列。分不出的地方也说明白——火只辖离、水只辖坎，单卦分不出阴阳，如实留空并写明原因，**不凑数**。

**跨载体不合并**：十干（庚／辛）与八卦（乾／兑）两处各自给出金的阴阳二分，但出自不同的书、谁也不给谁作证，所以页面上**两列并列、各挂出处**，绝不并成一张「补金之物」清单——并了就等于替书上做它没做过的对应。

## 功能

**占卜**（一事一占：起卦前静心默念所问，先过命局校验再选占法）

- **梅花易数**：端法起卦（一字／二字／多字声调／时间／物数）＋ AI 起卦（大白话描述，程序抽参数，配语音输入）；互卦变卦、体用五态、处方 R 按五态分支（**不是一律补身**）；**万物查卦三档**（精确／包含／检索词，**零类推**）＋ 查不到时形／色／性／位／体**五轴自推**；外应配卦四级次序
- **纳甲六爻**：摇杆六次（轨迹／时长／速度入种子，**每卦可原样复现回放**）；三钱法（老阳 1/8、少阴 3/8、少阳 3/8、老阴 1/8）；装卦纳甲／六亲／世应／六神；用神两档流程（高置信直断／歧义时先问）；伏神四出四不入；元忌仇神链；月日双裁判；贪生忘克
- **四柱八字**（**命局先行**）：真太阳时（经度×4 分＋均时差，可跨日）＋ 1986–1991 夏令时还原；节气定月令、藏干、十神、大运流年；格局取用、调候（取《穷通宝鉴》该月该干用神次序**首味**）
- **奇门遁甲**（时家·数理奇门）：拆补定局，排盘逐宫与书例成图一致
- **大六壬**：天地盘、四课三传，含类象层（类神取用／物类表／射覆，只给表与盘面事实，不下吉凶结论）

**研读与探索**

- **术语地图**：一句话定位 → 白话详解 → 关联术语互跳 → **原文语录**（术语库 199 词条 / 700 条关联）
- **移植行星**：长文研读入口，典籍引文逐字并标篇目，学派学说与编者推导分开标注

**我的与设置**

- **我的记录**：四层数据别混——命局档案（一次入库终身不变）／记录快照（可完整回放）／决策台账（完整推理链）／断言清单（可判定断言）
- **API 设置**：自带模型 key（地址由服务端名单写死，防本站被当任意地址转发器；key 只存本设备浏览器，服务器只在当次请求内存里使用，**不落盘、不写日志**）
- **公测反馈**

## 本地运行

### 环境

- Python 3.8+（后端）｜Node.js 16+（前端）
- **书库不随仓库分发**（受版权保护），见下文「测试」

### 后端

```bash
cd backend
pip install -r requirements.txt
cp .env.example .env      # 填入 LLM_API_KEY、SMTP、ASR 等
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

### 前端

```bash
cd frontend
npm install
npm run dev               # http://localhost:3001，/api 由 vite proxy 转发到 8000
```

Windows 下也可用仓库根的两个 bat：`start_backend.bat` / `start_frontend.bat`（含「已在运行则跳过」守护与端口占用提示）。

## 测试

```bash
cd backend
python -m pytest tests/     # 712 passed, 1 skipped
```

**38 个测试文件**，按对象分组：卦侧（起卦、三十六卦反查、三钱法概率、装卦书例、用神、伏神链）／命局侧（排盘、调候、格局、强弱、岁运）／判定侧（命卦校验、流动五行、质地与乘侮、择日、应期）／回检侧（判定级与提示级不许混报、白名单边界）／两步解卦侧（只看盘不扣额度、`ai=true` 恰好扣一次）／数据与安全侧（归属隔离、配额、备份往返）／依据侧（引文索引、术语库、外应逐字回源）。

**几条测试是「不许报」**——假阳性也是 bug，而且更贵（例：「不宜补土」不许被当成「宜补土」命中）。

**做过变异验证**：把 `if request.ai` 去掉后，相关断言立即转红——证明它真的在盯。

### 关于书库（逐字回源测试）

三条「逐字回源」防线需要底本 txt。按 **`BOOKS_DIR` 环境变量 → 仓库根 `books/` → 仓库同级 `books/`** 的次序查找；三处任一处有货就算生效。**语料缺席时会显式跳过并写明「当前未生效」，不会静默通过**——所以「0 跳过」本身就是「防线真在跑」的证据：

```powershell
$env:BOOKS_DIR = "D:\某处\books"
python -m pytest tests/
```

当前 1 条 skip 是 tzdata/zoneinfo 环境项（`test_bazi_dst.py`），与书库无关。

### 工程质量

- **确定性可复现**：同参数必出同卦，种子／三钱法／装卦全链可回放
- **边界清晰标注**：📜 直接原文 ／ 🔢 原文给次序、数值自定 ／ 🧩 由书理类比外推
- **宁缺毋假**：原文没直断的标「须详理」；取不到数据如实降级为占位标记，绝不编数字（例：黄历接口取不到时不生成「今日」数字）
- **归属隔离**：无令牌读取／删除／导出他人数据一律拒绝，令牌不符返回「与不存在同形」，不做存在性探测
- **降级不关站**：AI 不可用时给明确降级提示，判定与建议仍可用

## 设计铁律

1. **确定性归代码，语言归 AI，校准归人** —— 三件事各归一处，谁都不越界
2. **绝不代拟** —— 原文没有直断的地方标「须详理」，不给吉凶（例：外应「体生外应」「体克外应」，原文未直断，我们就不敢断）
3. **宁缺毋假** —— 取不到就如实降级，绝不编数字
4. **跨载体不合并** —— 分列两栏、各挂出处，不并成一张清单
5. **书上分几层，建议就分几层** —— 不硬拆，也不凑数

## 局限性（分三级，逐条列明）

### 甲 · 已定案 10 条（我们自己定的规矩，书上没有明写）

含：确定性归代码／证据三级／绝不代拟／**从格成格时调候让位**（书给了扶抑与调候两条路线，**没说冲突时谁优先**，我们从「格局不可逆」之义定）／多应取「先见者」为主应／跨载体不合并／S·M·L 三档（解卦三档相同，只有行动建议按档加厚）／命局档案一次入库终身不变／记录可回放·软删除 30 天／**设备即账户**（一枚随机令牌，无注册无手机号）。

### 乙 · 待校准 13 项数值

旺相休囚死权重、引动参与阈值、强弱四态分档、乘侮带宽、月令加成、藏干权重、得令/得地/得势（50/30/20）、强弱五档分界、特殊加减、宜日状态、边界样本带宽、择日窗口、校准护栏——全部标注「工程默认值，未经案例校准，仅参与比较／求和」，校准方式是**敏感度分析与反例捕捉**，不是拟合「最优值」。

### 丙 · 尚未完成（已登记、知道怎么做、还没做）

1. **风水空间定点、姓名学** —— 屋宅建议只到方位与布局，不做具体定点（需实地与罗盘，且**没有书证就不做**）
2. **长期反馈触达** —— 令牌持久化＋回执码＋日历提醒已做；邮件提醒与**失联率可见**（有多少断言因用户失联永远无法验证，必须显示出来，不能只报应验率）待决策
3. **单机单库** —— 一台服务器、一个 SQLite 库，多进程/多机部署时各算各的，尚无分布式
4. **回检只做到「判定级」自动** —— 语义级改写长期留给人看，不假装机器能兜
5. **解卦长度上限** —— 撞上限已不静默，但上限仍是 4096 tokens，偏长的几卦仍会断
